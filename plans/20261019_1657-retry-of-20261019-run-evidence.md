## 4. `A17` — first real run

`A17` (`v3.7.6`) caps browser sweeps at 3 at a time and non-browser at 15. From Stage A's per-subagent
transcripts (lifetime windows; 89 subagents, 15 used Chrome tools):

| Lane | Cap | Stage A peak | This session's retry |
|---|---|---|---|

| Non-browser | 15 | **18** | n/a |
| All | 20 (hard) | **20** — one dispatch was refused and re-dispatched | 9 |

The browser overshoot has a specific cause: at 15:08:03 Stage A dispatched two browser sources in the same
instant (LinkedIn search and the Phase 3 X search) while two others were still running. The caps are prose
the orchestrating model counts itself; my retry held 3 by starting the next agent only when one returned.
n = 1 run of each, and this run's browser sweeps all ended in about a minute at the login wall, so
**what this run cannot show is whether the cap prevents the stalls it was written for.** The retry's
logged-in sweeps saw a different failure: X search throttling ("Something went wrong") in at least six
sweeps, which no tab-count cap addresses.
